## README.md

### Описание проекта

Проект предоставляет инструменты для обработки финансовых данных с учётом обработки ошибок и исключений. Основное внимание уделено безопасности конфиденциальной информации и надёжности операций.

### Основные компоненты

#### 1. Маскирование данных (Masks)

Модуль масок отвечает за обработку конфиденциальной информации.

**Маскирование карт:**
* Формат вывода: `XXXX XX** **** XXXX`.
* Требования к входным данным: минимум 10 цифр.
* При нарушении требований выбрасывается исключение `ValueError` с информативным сообщением.

**Маскирование счетов:**
* Формат вывода: **` XXXX` (отображаются только последние 4 цифры).
* При некорректных данных выбрасывается исключение `ValueError`.

**Примеры обработки ошибок в маскировании:**

```python
from src.masks import get_mask_card_number

try:
    # Попытка обработать некорректный номер карты (менее 10 цифр)
    get_mask_card_number('1234')
except ValueError as e:
    print(f"Ошибка: {e}")  # Выведет: "Номер карты должен содержать не менее 10 цифр"

try:
    # Пустая строка
    get_mask_card_number('')
except ValueError as e:
    print(f"Ошибка: {e}")  # Выведет: "Номер карты не содержит цифр"
```
2. Обработка транзакций (Processing)

Модуль обработки предоставляет функционал для работы с транзакциями.

Основные возможности:

    Фильтрация транзакций по состоянию.

    Поддержка статусов: EXECUTED, CANCELED.

    Обработка запросов с несуществующими статусами.

Пример обработки ошибок фильтрации:
python

```python
from src.processing import filter_by_state

transactions = [
    {'id': 414288290, 'state': 'EXECUTED'},
    {'id': 594226727, 'state': 'CANCELED'}
]

try:
    # Попытка фильтрации по несуществующему статусу
    result = filter_by_state(transactions, 'UNKNOWN_STATE')
    if not result:
        print("Транзакции с таким статусом не найдены")
except Exception as e:
    print(f"Произошла ошибка: {e}")
```
3. Виджеты (Widget)

Модуль виджетов обеспечивает:

    форматирование дат;

    маскирование информации в интерфейсе.

Примеры обработки ошибок виджетов:
```python

from src.widget import get_date, mask_account_card

try:
    # Корректная дата
    print(get_date('2024-03-11T02:26:18.671407'))

    # Некорректный формат даты
    print(get_date('2024-03-11'))
except ValueError as e:
    print(f"Ошибка формата даты: {e}")

try:
    # Некорректный формат карты (слишком короткий номер)
    mask_account_card('123456789')
except ValueError as e:
    print(f"Ошибка маскирования: {e}")
```
Модуль загрузки данных из файлов

Модуль предоставляет функции для загрузки транзакций из CSV и XLSX файлов:
```python
    load_transactions_from_csv(filename) # загрузка из CSV.

    load_transactions_from_xlsx(filename) # загрузка из XLSX.
```
Обе функции возвращают список транзакций или пустой список в случае ошибки.

Тестирование
Типы тестов

В проекте реализованы следующие типы тестов:

    Unit‑тесты — проверка отдельных функций на корректность работы.

    Integration‑тесты — проверка взаимодействия между компонентами системы.

    Negative‑тесты — проверка обработки ошибочных и крайних случаев.

    Performance‑тесты — оценка производительности критических участков кода.

Принципы тестирования

Все тесты организованы в соответствии с принципами:

    Изолированность — каждый тест независим от других.

    Повторяемость — результаты тестов стабильны при повторных запусках.

    Полнота — охват всех возможных сценариев использования и обработки ошибок.

    Читаемость — код тестов понятен и легко поддерживаем.

Тесты для модулей загрузки данных

Тесты для проверки загрузки транзакций из файлов покрывают следующие сценарии:

Для CSV‑файлов (csv_reader_test.py):

    test_load_csv_success — успешная загрузка данных из корректного CSV‑файла.

    test_load_csv_file_not_found — обработка случая несуществующего файла.

    test_load_csv_invalid_extension — обработка файла с неправильным расширением.

    test_load_csv_critical_error — обработка критической ошибки при чтении файла (имитация сбоя pandas.read_csv).

Для XLSX‑файлов (xlsx_reader_test.py):

    test_load_xlsx_success — успешная загрузка данных из корректного XLSX‑файла.

    test_load_xlsx_file_not_found — обработка случая несуществующего файла.

    test_load_xlsx_invalid_extension — обработка файла с неправильным расширением.

    test_load_xlsx_critical_error — обработка критической ошибки при чтении файла (имитация сбоя pandas.read_excel).

Примеры тестовых фикстур

Для создания временных тестовых файлов используются фикстуры pytest:
```python

import pandas as pd
```

```python
@pytest.fixture
def temp_csv(tmp_path):
```

# Фикстура для создания временного XLSX

Требования к обработке ошибок

    Все ошибки должны обрабатываться через исключения.

    Для каждой функции определены конкретные типы исключений.

    Сообщения об ошибках должны быть понятными и информативными.

    Рекомендуется оборачивать вызовы функций в блоки try-except.

Рекомендации по использованию

    Всегда оборачивайте вызовы функций в блоки try‑except.

    Проверяйте входные данные перед обработкой.

    Обрабатывайте специфические исключения для каждого модуля.

    Используйте информативные сообщения об ошибках для упрощения отладки.

    При разработке новых функций добавляйте соответствующие тесты в соответствующую директорию tests/.
